# PBRES 自检与交付复查

封包之后的复查覆盖归档、语义和来源对照三类。归档部分由 `pbres:pack` 的正式校验与回读产出结论，本文件补充需要人工判断的部分。这个 skill 只做转换：不新建测试、测量页或渲染夹具，也不为验收运行仓库测试套件。

## 1. 正式回读与包结构

`pbres:pack` 在写出产物后已经执行 Contract、语义与模板引用校验，并对产物再次 `loadPbres` 回读；把它的版本与摘要记入报告即可。用 `pbres:unpack` 展开产物复核以下事实：

- 包元数据、目标系统、许可、资源路径、空目录与模板引用合法；
- 所有资产存在、SHA-256/字节数/尺寸/媒体类型匹配，且无外部图片依赖。

不要用普通 ZIP 工具打开、也不要手写归档来替代这一步。

## 2. 数量、身份与目录

生成对账表：来源候选数 = converted + skipped + pending。再核对输出资源数，解释合法的拆分/合并差额。

检查资源 ID 唯一、路径无碰撞、目录层级符合用户要求、顺序合理。检查同名资源是否真是合法重名，不把同名自动去重。

## 3. 字段完整性

逐资源把 `data` 与其精确的当前 Template Schema 和 `defaultData` 比较：

- 必填字段全部存在；
- 字段名无错别字、旧名称、展示名称或意外别名；
- 没有因解析失败而遗漏来源字段；
- 字符串、数组、对象类型正确，结构化数据未变成 JSON 文本；
- 枚举、数值字符串和嵌套特性结构符合 Schema；
- 来源缺失导致的空值与漏键得到区分；
- 简介、普通字段、自由字段和规则特性没有互相错放；
- 名称、原文、数值、规则描述、强调和特性顺序与来源一致。

自由模板的任意字段也必须是 Schema 允许的类型；字段自由不等于可以漏掉固定字段或随意改变`内容`结构。

对全量运行结构检查，并人工对照以下样本：每种模板至少一张、首项、末项、最长名称、最长简介、最长单项特性、特性最多、来源缺字段、拆分/合并、同名、带图、无图和自由模板资源。

## 4. 图片与署名

- 抽查图片确实对应资源，不只验证文件存在；
- 检查 WebP、当前资源图片输出策略、显示方向和裁剪结果；
- 检查 artwork credit 与 source label 没有丢失或串卡；
- 对重名和多图记录逐一确认映射证据。

## 5. 内容容量交给用户

不量卡面像素高度、不截图、不做渲染回归：卡面尺寸与自动字号由共享渲染器按 presentation 自行处理，不属于本次转换的交付条件。

只做语义侧的容量排查，按顺序看：

1. 是否字段映射错误，把数组序列化成文本或把多段内容塞入单字段；
2. 是否重复提取、重复换行、残留 Markdown/HTML 或无关文本；
3. 是否使用了错误模板或 presentation。

前 3 项按语义修正后重新封包。若来源内容本身确实超出该模板的表达能力，把具体资源、位置和可选处理方式交给用户决定，例如更换展示模式、取消固定比例、拆分资源或调整文字；不擅自截断简介或规则、缩写术语、隐藏特性或改字号来掩盖问题。

## 6. 最终报告

报告至少包含：

- `pbres:pack` 的版本、摘要与回读结果，以及 `pbres:unpack` 复核结论；
- 来源与输出数量对账；
- 模板及字段检查结果；
- 图片和署名检查结果；
- 按第 5 项语义排查得到的问题清单（如有）；
- 所有 `pending` 项及需要用户作出的决定。

只要存在未裁定的语义问题或需要用户决定的容量问题，就将其明确标为未完成，不用笼统的“检查通过”覆盖。
