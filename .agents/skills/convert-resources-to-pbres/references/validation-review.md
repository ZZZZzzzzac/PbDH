# PBRES 验证与复查

验证必须同时覆盖归档、语义和真实渲染。任何一类未完成都不能报告转换完成。

## 1. 正式回读与包结构

- 使用当前 `loadPbres` 或正式导入流程回读最终字节；
- 确认 Contract、包元数据、目标系统、许可、资源路径、空目录、模板引用和摘要合法；
- 确认所有资产存在、SHA-256/字节数/尺寸/媒体类型匹配，且无外部图片依赖；
- 确认输出文件能在 Creator 导入，而不只是在临时脚本中解析。

## 2. 数量、身份与目录

生成对账表：来源候选数 = converted + skipped + pending。再核对输出资源数，解释合法的拆分/合并差额。

检查资源 ID 唯一、路径无碰撞、目录层级符合用户要求、顺序合理。检查同名资源是否真是合法重名，不把同名自动去重。

## 3. 字段完整性

逐资源把 `data` 与其精确的当前 Template Schema 和 `defaultData` 比较：

- 必填字段全部存在；
- 字段名无错别字、旧名称、展示名称或意外别名；
- 没有因解析失败而遗漏来源字段；
- 字符串、数组、对象类型正确，结构化数据未变成 JSON 文本；
- 枚举、数值字符串和嵌套特性结构符合 Schema；
- 来源缺失导致的空值与漏键得到区分；
- 简介、普通字段、自由字段和规则特性没有互相错放；
- 名称、原文、数值、规则描述、强调和特性顺序与来源一致。

自由模板的任意字段也必须是 Schema 允许的类型；字段自由不等于可以漏掉固定字段或随意改变`内容`结构。

对全量运行结构检查，并人工对照以下样本：每种模板至少一张、首项、末项、最长名称、最长简介、最长单项特性、特性最多、来源缺字段、拆分/合并、同名、带图、无图和自由模板资源。

## 4. 图片与署名

- 抽查图片确实对应资源，不只验证文件存在；
- 检查 WebP、当前资源图片输出策略、显示方向和裁剪结果；
- 检查 artwork credit 与 source label 没有丢失或串卡；
- 对重名和多图记录逐一确认映射证据。

## 5. 真实卡面高度与布局

把最终 PBRES 导入 Creator，用共享真实 Renderer 查看，不用字符数或 JSON 长度代替渲染验收。覆盖包内所有模板和 presentation 组合；大量同构资源可全量自动检测并配合高风险样本截图复核。

对卡面 DOM 或等价渲染结果检查：

- 固定比例卡保持目标宽高比，外框高度没有被内容撑长；
- 内容容器没有 `scrollHeight > clientHeight` 的裁切或隐藏溢出；
- 标题、原文、标签、特性框和 footer 没有越界、遮挡或重叠；
- 最长内容与最多特性的卡片没有被截断；
- 图文、纯文、纯图，以及固定比例/非固定比例模式均按实际存在情况覆盖；
- 卡片在 Player 资源库选择器等真实消费界面仍能正常显示。

发现溢出时按顺序排查：

1. 是否字段映射错误，把数组序列化成文本或把多段内容塞入单字段；
2. 是否重复提取、重复换行、残留 Markdown/HTML 或无关文本；
3. 是否使用了错误模板或 presentation；
4. 内容本身是否确实超过设计容量。

前 3 项可在不改变语义的前提下修正并重验。第 4 项必须把具体卡片、溢出位置和选项交给用户决定，例如调整展示模式、取消固定比例、拆分资源或修改文字。不得擅自截断简介或规则、缩写术语、隐藏特性或改字号来掩盖问题。

## 6. 最终报告

报告至少包含：

- `loadPbres`/Creator 导入结果；
- 来源与输出数量对账；
- 模板及字段检查结果；
- 图片和署名检查结果；
- 卡面高度/溢出检查覆盖范围与失败清单；
- 所有 `pending` 项及需要用户作出的决定。

只要存在未裁定的语义问题或未处理的真实溢出，就将其明确标为未完成，不用笼统的“验证通过”覆盖。
