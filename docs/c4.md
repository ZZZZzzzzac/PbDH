# PbDH 平台 C4 架构图

本文记录 PbDH 平台当前已经确定的系统上下文与运行容器。为避免连线交叉，每个关注点使用独立视图；这些视图共同构成当前 C4 模型，不应合并为一张总图。

## 阅读规则

- 产品 PRD 层级与 C4 层级是两套不同视角。
- PRD L1 按用户价值和产品验收边界划分；C4 Container 按运行、部署和存储边界划分。
- `Platform Backend` 是 C4 Container 和部署边界，不是产品 L1。
- `Contracts & Template Platform` 是产品 L1，但不对应一个必须在线运行的同名容器。
- 尚未由 L1/L2 PRD 定义的 C4 Component 与 Code 结构不在本文预设。
- 箭头表示依赖或数据流向，不表示共享数据所有权。

## C4 L2：运行容器

### 产品入口与后端

此图回答：用户分别进入哪个前端，哪些前端使用自托管后端？

```mermaid
flowchart LR
    author["系统包作者"] --> authoring["系统包创作工具链"]
    player["玩家"] --> playerApp["Player App"]
    creator["创作者"] --> creatorApp["Creator App<br/>卡牌工坊 + GM Tabletop"]
    gm["GM"] --> creatorApp
    consumer["资源消费者"] --> marketApp["Market 前端"]

    playerApp --> backend["Platform Backend<br/>模块化单体"]
    creatorApp --> backend
    marketApp --> backend

    authoring -. "复用系统包加载与玩家运行时预览" .-> playerApp
```

`Platform Backend` 为一个自托管模块化单体，提供身份映射、云同步、托管媒体和市场 API。它服务多个产品，但自身不是产品 L1。

### 本地优先与云同步

此图回答：哪些文档在本地保存并同步到云端？统一账号不合并这些领域数据。

```mermaid
flowchart LR
    subgraph playerDomain["玩家域"]
        playerApp["Player App"] <--> playerLocal[("角色存档<br/>本地资源")]
    end

    subgraph creatorContainer["Creator App"]
        creatorApp["Creator App 组合根"]
        subgraph creatorDomain["Creator L1 文档"]
            creatorLocal[("Creator Workspace")]
        end
        subgraph gmDomain["GM Tabletop L1 文档"]
            gmLocal[("Tabletop Document")]
        end
        creatorApp <--> creatorLocal
        creatorApp <--> gmLocal
    end

    playerApp --> sync["Cloud Sync API"]
    creatorApp --> sync

    sync --> playerCloud[("角色云文档")]
    sync --> creatorCloud[("工作区云文档")]
    sync --> gmCloud[("桌面云文档")]
```

Cloud Sync 共享同步机制，不创建跨领域统一工作区，也不授予一个领域修改另一个领域文档的权限。

### 账号、业务数据与媒体

此图回答：Supabase 与自托管基础设施分别保存什么？

```mermaid
flowchart LR
    apps["Player / Creator（含 GM Tabletop）/ Market"] -->|"身份令牌与业务请求"| backend["Platform Backend"]

    backend -->|"验证身份令牌"| supabase["Supabase Auth"]
    backend --> identity[("PbDH 账号映射")]
    backend --> publications[("市场出版物")]
    backend --> documents[("私有云文档")]
    backend --> assets[("托管媒体资产<br/>WebP + 内容寻址")]
```

Supabase 只承担外部身份认证，不保存 PbDH 结构化业务数据或媒体资产。

### 共享运行能力

此图回答：前端如何复用合约、模板、渲染、转换与桌面能力？图中连接表示构建或运行时模块依赖，不是网络调用。

```mermaid
flowchart TB
    contracts["平台合约"]
    templates["资源模板<br/>Template Registry"]
    conversion["资源转换核心"]
    renderer["资源渲染器"]
    tabletop["卡牌桌面核心"]

    contracts --> templates
    contracts --> conversion
    contracts --> renderer
    contracts --> tabletop
    templates --> conversion
    templates --> renderer
    renderer --> tabletop

    player["Player App"] --> conversion
    player --> renderer
    player --> tabletop

    creator["Creator App"] --> conversion
    creator --> renderer
    creator --> tabletop

    market["Market 前端"] --> renderer
```

共享模块不拥有应用数据，不形成共享可变状态，也不要求各应用锁步发布。应用组合根负责解析资源模板并注入所需能力。

## 关键动态视图：资源快照流转

此图不是新的容器图，用于补充 C4 静态结构无法表达的更新边界。

```mermaid
flowchart LR
    draft["创作者工作区<br/>可变草稿"]
    package["资源包快照"]
    publication["市场出版物<br/>明确快照"]
    playerLibrary["Player<br/>本地资源库"]
    creatorWorkspace["Creator Workspace<br/>可变资源项目"]
    instance["桌面实例资源副本"]

    draft -->|"明确打包"| package
    package -->|"明确安装或更新"| playerLibrary
    package -->|"导入、打开或 Fork"| creatorWorkspace
    package -->|"明确发布"| publication
    publication -->|"明确安装或更新"| playerLibrary
    publication -->|"在 Creator / GM Tabletop 中打开"| creatorWorkspace
    creatorWorkspace -->|"每次显式放置都复制"| instance

    draft -. "不会自动更新" .-> publication
    publication -. "不会自动更新" .-> playerLibrary
    creatorWorkspace -. "不会更新既有实例" .-> instance
```

资源更新以显式快照替换为边界：创作者编辑不会自动更新市场；市场发布不会自动更新 Player 或 Creator Workspace；Creator Workspace 修改不会改变既有桌面实例。Market 打开 GM Tabletop 时只导入或打开完整 Workspace 并聚焦上下文，不能自动放置。
