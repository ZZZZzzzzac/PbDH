# 正式 UI 设计源

## 用途

本目录存放已进入实现阶段的 OpenPencil `.op` 文件。GitHub PRD 负责产品能力、行为与验收边界；本目录的 `.op` 负责已覆盖界面的视觉、布局、组件层级与状态表现。

## 文件与命名

- 一个产品入口一个文件：`creator-app.op`、`player-app.op`、`market.op`。
- GM Tabletop 使用 `creator-app.op` 内的独立页面，不建立独立 App 设计文件。
- 页面使用 `00 PRD Coverage`、`01 User Flows`、`10 ...`、`11 States & Conflicts`、`20 Dialogs & Menus`、`30 Components` 命名；Frame 使用 `Issue-US / Product / Capability / State` 命名。
- 供生成器读取的节点必须使用稳定语义名称，禁止依赖 OpenPencil 自动节点 ID。
- Canonical Card Surface 每个 Renderer Revision 只保留一份设计。Creator、Player、GM Tabletop 与 Market 必须渲染同一资源表面；宿主缩放、选中态、异常媒体和私有数据属于运行状态或外壳，不复制成多份卡面设计。
- 敌人 portrait 是可选媒体：未声明 portrait 的纯文字卡复用同一 Canonical Card Surface，但完全折叠媒体区，卡面从名称开始；已声明但缺失或解码失败的媒体仍按异常状态处理，不降级伪装成纯文字卡。
- 卡面尺寸由内容密度和可读性决定，不预设 `63×88mm`。调整尺寸时优先保证主要规则内容可读，敌人特性正文不得作为压缩目标。
- OpenPencil 同级节点顺序就是绘制和 z-index 顺序，并且列表中更靠前的节点显示在更上层。卡面图层按“标题/徽标等前景 → 遮罩 → 背景媒体”排列；调整层级必须移动节点顺序，不能只靠视觉重叠碰巧正确。
- 所有 Text 节点必须用用途命名，如 `标题 / 中文名`、`特性 / 蓄力 / 正文`；禁止保留默认 `Text`。文本必须保存在 Text 节点的 `content` 中并保持未锁定，以便用户在 OpenPencil 内直接编辑。
- Creator Workspace 的资源导航采用 IDE 文件管理器式紧凑目录树：文件夹可展开，资源使用单行文件项，常规行高保持在 `24–28px`；不得用资源卡片承载目录，以免上百资源时降低信息密度。
- 资源文件的前置标志由 Template Registry 提供，每个 Template 使用独立、可辨识的图形标志；不得由中文或英文首字母自动生成，以免名称冲突或缩小后不可读。
- Player 车卡器、Creator 卡片工坊、GM 桌面和 Market 资源市场共用同一 Platform App Bar；主页面切换与账号等全局操作放在该栏，资源包导入导出等领域操作留在所属工作区。
- 从旧产品迁移的 App 自有顶栏必须并入 Platform App Bar，不能在共同应用栏下方再叠一条同级顶栏。旧 Player 的玩家功能、玩家存档、导入导出和系统包菜单作为 Player 专属操作保留在共同应用栏内。
- Player 从 `PbDH_sheet` 迁移资源管理器与弹窗时只继承功能、状态和确认语义；视觉统一使用当前 Creator 的暖色高密度面板、深色顶栏、酒红主操作与语义状态色，不复制旧 Sheet 的方框列表和内联警告条样式。
- 产品界面默认只展示用户可识别的资源包名称、版本、数量、来源、兼容结果、许可与可行动诊断。Package/System/Template ID、Digest、Contract 版本和内部路由名不得作为常驻说明文字；仅在错误详情、复制诊断或开发视图中按需展开。
- Creator 资源编辑沿用已验收的 IDE 标签行为：单击目录项打开可被替换的临时标签，双击、编辑或显式固定后成为常驻标签；允许同时打开多个资源并逐个关闭。
- Creator 的资源标签栏位于资源导航右侧的整个工作区顶部，横跨编辑区与预览区；编辑内容和实时预览在标签栏下方并列，避免标签数量受编辑栏宽度限制。
- Creator 编辑字段按 Canonical Card Surface 的阅读顺序排列，不使用“基础信息”“战斗数据”等卡片分组或分段导航。短值字段采用紧凑定宽输入，字段名与输入框同一行，避免为少量字符保留大块空白。
- Creator 的同行字段必须落在统一列网格上：同类字段使用相同标签宽度、输入高度、字号与列宽。允许用无标题的浅色分组面板和细分割线组织密集字段，但不得重新引入冗余分组标题。
- 特性编辑始终展开，并分别提供可编辑的特性名、特性类型和特性描述；短字段与长描述使用不同宽度，不把三者合并为摘要或折叠项。
- 特性更多操作必须提供“清空内容”和“删除特性”；删除进入明确确认态，不允许无反馈的装饰性菜单按钮。
- 卡面预览提供“纯文字 / 半图半文字 / 纯图片”三种表现模式，以及独立的“固定比例”开关。关闭固定比例时卡面高度随内容增长；开启后保持 Template 声明尺寸并截断溢出内容，用创作约束阻止长篇正文，不缩小字体或自动放大卡面。
- 产品界面只保留操作、字段、名称、状态、诊断和必要元数据；设计同步规则、能力解释、使用提示等说明性注释不得写入产品页面。

## 单向同步

- 同步方向固定为：正式 `.op` → `scripts/` 中的生成器 → `*.generated.ts` / 映射报告 → React/CSS。
- 生成文件不得手改。设计调整先改 `.op`，再运行生成与验证。
- React 可包含事件处理、可访问性和数据绑定等 `.op` 无法表达的实现逻辑；视觉常量与结构差异必须能追溯到 `.op` 或显式例外。
- localhost、PNG、PDF 和 HTML 只作验收结果，不作为设计输入。

## 验证

- 修改正式 `.op` 后必须运行对应生成器，并确认生成文件无陈旧差异。
- 生成器必须在语义节点缺失、名称重复、尺寸或结构不满足约定时失败，不得静默使用默认值。
- 视觉验收同时检查 OpenPencil 截图与真实 App；发现差异时修正映射或回到 `.op` 决策，禁止直接在两端分别调值。
