# 正式 UI 设计源

## 用途

本目录存放已进入实现阶段的 OpenPencil `.op` 文件。GitHub PRD 负责产品能力、行为与验收边界；本目录的 `.op` 负责已覆盖界面的视觉、布局、组件层级与状态表现。

## OpenPencil 工具入口

- 当前工作机的 OpenPencil CLI 固定为 `C:\Program Files\OpenPencil\op.exe`；它未加入 `PATH`，不得因为直接执行 `op` 失败就判断 CLI 未安装。
- PowerShell 中统一使用 `$opCli = 'C:\Program Files\OpenPencil\op.exe'`，再以 `& $opCli <command>` 调用。开始修改前先运行 `& $opCli --version` 与 `& $opCli status` 确认入口和服务状态。
- OpenPencil 设计 Skill 位于 `C:\Users\zinge\.codex\skills\openpencil-design\SKILL.md`。涉及 `.op` 读取、创建或修改时必须先完整读取该 Skill，并按其中的 CLI、节点语义、Text 可编辑性和 `design:refine` 规则执行。
- 优先通过 CLI 操作已打开的 OpenPencil 文档；需要无人值守处理时使用 `& $opCli start --headless --file <absolute-path>`。不得把浏览器自动化作为默认替代方案。
- CLI 或 Skill 确实不可用时必须明确报告，不得静默维护第二套手写设计真相源。

## 文件与命名

- 一个产品入口一个文件：`creator-app.op`、`player-app.op`、`market.op`。
- GM Tabletop 使用 `creator-app.op` 内的独立页面，不建立独立 App 设计文件。
- 页面使用 `00 PRD Coverage`、`01 User Flows`、`10 ...`、`11 States & Conflicts`、`20 Dialogs & Menus`、`30 Components` 命名；Frame 使用 `Issue-US / Product / Capability / State` 命名。
- 供生成器读取的节点必须使用稳定语义名称，禁止依赖 OpenPencil 自动节点 ID。
- Canonical Card Surface 每个 Renderer Revision 只保留一份设计。Creator、Player、GM Tabletop 与 Market 必须渲染同一资源表面；宿主缩放、选中态、异常媒体和私有数据属于运行状态或外壳，不复制成多份卡面设计。
- 敌人 portrait 是可选媒体：未声明 portrait 的纯文字卡复用同一 Canonical Card Surface，但完全折叠媒体区，卡面从名称开始；已声明但缺失或解码失败的媒体仍按异常状态处理，不降级伪装成纯文字卡。
- 卡面尺寸由内容密度和可读性决定，不预设 `63×88mm`。调整尺寸时优先保证主要规则内容可读，敌人特性正文不得作为压缩目标。
- OpenPencil 同级节点顺序就是绘制和 z-index 顺序，并且列表中更靠前的节点显示在更上层。卡面图层按“标题/徽标等前景 → 遮罩 → 背景媒体”排列；调整层级必须移动节点顺序，不能只靠视觉重叠碰巧正确。
- 所有 Text 节点必须用用途命名，如 `标题 / 中文名`、`特性 / 蓄力 / 正文`；禁止保留默认 `Text`。文本必须保存在 Text 节点的 `content` 中并保持未锁定，以便用户在 OpenPencil 内直接编辑。
- Creator Workspace 的资源导航采用 IDE 文件管理器式紧凑目录树：文件夹可展开，资源使用单行文件项，常规行高保持在 `24–28px`；不得用资源卡片承载目录，以免上百资源时降低信息密度。
- 资源文件的前置标志由 Template Registry 提供，每个 Template 使用独立、可辨识的图形标志；不得由中文或英文首字母自动生成，以免名称冲突或缩小后不可读。
- Player 车卡器、Creator 卡片工坊、GM 桌面和 Market 资源市场共用同一 Platform App Bar；主页面切换与账号等全局操作放在该栏，资源包导入导出等领域操作留在所属工作区。
- 从旧产品迁移的 App 自有顶栏必须并入 Platform App Bar，不能在共同应用栏下方再叠一条同级顶栏。旧 Player 的玩家功能、玩家存档、导入导出和系统包菜单作为 Player 专属操作保留在共同应用栏内。
- Player 从 `PbDH_sheet` 迁移资源管理器与弹窗时只继承功能、状态和确认语义；视觉统一使用当前 Creator 的暖色高密度面板、深色顶栏、酒红主操作与语义状态色，不复制旧 Sheet 的方框列表和内联警告条样式。
- 产品界面默认只展示用户可识别的资源包名称、版本、数量、来源、兼容结果、许可与可行动诊断。Package/System/Template ID、Digest、Contract 版本和内部路由名不得作为常驻说明文字；仅在错误详情、复制诊断或开发视图中按需展开。
- Creator 资源编辑沿用已验收的 IDE 标签行为：单击目录项打开可被替换的临时标签，双击、编辑或显式固定后成为常驻标签；允许同时打开多个资源并逐个关闭。
- Creator 的资源标签栏位于资源导航右侧的整个工作区顶部，横跨编辑区与预览区；编辑内容和实时预览在标签栏下方并列，避免标签数量受编辑栏宽度限制。
- GM Tabletop 必须复用 Creator 的完整工作区壳层：顶部应用栏和左侧资源导航与 Creator 保持同一结构、尺寸及操作；原资源标签栏位置改为多个 Tabletop Document 标签，只有其下方的内容与预览主体切换为桌面画布。不得另设桌面文档侧栏、来源浏览器或实例检查器。
- GM 编辑桌面实例资源副本时，必须复用该 Template 已有的武器编辑器、敌人编辑器等创作输入布局及 Canonical Card Surface 预览；宿主只切换数据目标和允许的 Capability，不建立通用实例字段检查器。
- GM Tabletop 中从 Creator Workspace 资源导航打开的资源仍使用 Creator 编辑语义，写入 Workspace 中的来源资源；从桌面实例进入同一编辑器时则写入该实例私有资源副本。两条路径必须通过数据绑定目标和界面状态明确区分，任何一方都不得自动更新或回写另一方。
- Creator 编辑器和 GM 实例编辑器的预览区域使用与桌面画布一致的浅色工作台主题，视觉上表现为缩小的桌面视口；深色外壳不得让同一 Canonical Card Surface 看起来处于另一套宿主主题。
- Creator 编辑字段按 Canonical Card Surface 的阅读顺序排列，不使用“基础信息”“战斗数据”等卡片分组或分段导航。短值字段采用紧凑定宽输入，字段名与输入框同一行，避免为少量字符保留大块空白。
- Creator 的同行字段必须落在统一列网格上：同类字段使用相同标签宽度、输入高度、字号与列宽。允许用无标题的浅色分组面板和细分割线组织密集字段，但不得重新引入冗余分组标题。
- 特性编辑始终展开，并分别提供可编辑的特性名、特性类型和特性描述；短字段与长描述使用不同宽度，不把三者合并为摘要或折叠项。
- 特性更多操作必须提供“清空内容”和“删除特性”；删除进入明确确认态，不允许无反馈的装饰性菜单按钮。
- 卡面预览提供“纯文字 / 半图半文字 / 纯图片”三种表现模式，以及独立的“固定比例”开关。关闭固定比例时卡面高度随内容增长；开启后保持 Template 声明尺寸并截断溢出内容，用创作约束阻止长篇正文，不缩小字体或自动放大卡面。
- 产品界面只保留操作、字段、名称、状态、诊断和必要元数据；设计同步规则、能力解释、使用提示等说明性注释不得写入产品页面。
- GM 桌面使用白板手势，不设置“平移 / 选择 / 放置”工具模式：左键选择并实时拖动实例，中键或右键拖动空白处平移，`Ctrl + 滚轮`缩放；资源只能从左侧资源导航拖入桌面完成放置。实例按整体图片处理，必须禁止浏览器文字选择与原生图片拖拽；暂不提供左键框选多选。
- GM 桌面实例的编辑、复制、删除只放在实例右键菜单；空白桌面右键菜单承载重命名、打印、导入、导出和删除桌面等桌面级操作。新建桌面必须先输入名称，既有桌面通过空白桌面右键菜单重命名；名称随 Tabletop Document 持久化。桌面没有独立的“关闭”状态，标签上的 `×` 与空白桌面右键菜单中的“删除桌面”都进入同一个二次确认，确认后删除 Tabletop Document。右键发生拖动时执行平移，未发生拖动时才打开对应菜单。
- Creator 与 GM 共用同一资源工作区，资源右键菜单不得提供“发送到桌面”或桌面选择子菜单。进入 GM 页面后直接浏览共享工作区，并从左侧资源导航拖入当前桌面完成放置。
- Market 使用公开目录与 Publication 详情布局，不复制 Creator 的 IDE 工作区。搜索结果可以从包内资源进入详情，但取得操作始终以完整 Resource Package 为单位；单资源入口只保留当前资源的聚焦定位。
- Market Publication 详情只展示用户可判断的当前版本、作者、更新时间、许可、内容语言、目标系统和包内资源；不得提供历史版本选择、资源编辑、`.pbres` 上传或本地安装状态。
- Market 的取得入口固定为匿名“下载 .pbres”、交接 Player、导入卡片工坊和“发送到桌面”。下载只保留在 Publication 详情的一级取得操作中，交接确认与失败等二级窗口不得重复显示下载入口。“导入卡片工坊”和“发送到桌面”都通过 Creator 的同一入口把完整资源包导入共享工作区；后者只切换到 GM 页面，不在 Market 交接中选择或新建桌面，也不自动放置资源。目标 App 的候选校验、冲突确认和资源路由必须绘制为目标 App 自己的界面状态。
- Market 的 Creator 发布界面只接收当前完整资源包快照，展示元数据编辑与快照发布分离。发布、更新、撤回、恢复和失败状态必须明确显示当前公开版本；不得暗示远端更新会修改或召回本地副本。
- Creator 发布完成后必须显示明确结果反馈，区分首次发布、更新已有出版物和内容完全相同而跳过；失败继续使用可行动诊断，不得把成功静默处理。
- Market 响应式设计必须保留搜索、详情、匿名下载和全部 App 交接入口。移动端将筛选与次级操作收入浮层，但不得降级为只读页面。
- Platform App Bar 在 Player、Creator/GM 与 Market 中使用同一结构：高度 `56px`，左右各保留 `220px` 固定区，中间放主页面导航；当前页面使用底部 `2px` 酒红标记，禁止各 App 改成独立胶囊标签、改变导航位置或新增全局搜索框。
- `creator-app.op` 中首个 `Creator / 顶部应用栏` 是 Platform App Bar 结构源；修改后运行 `npm run sync:platform-app-bar` 投影到 Player 与 Market，再运行各自设计生成器。目标文件只允许调整当前页面状态，不得独立修改结构和视觉常量。
- Market 桌面发现页只在左侧筛选栏提供搜索，筛选栏宽度固定为与 Creator/GM 资源导航相同的 `250px`；不得在顶部应用栏或内容顶部重复搜索与筛选工具栏。
- Market 的每个筛选维度使用独立浮动下拉菜单。选项前使用 checkbox，可单选或多选；同一维度内多项按 OR 匹配，不同维度之间按 AND 匹配。下拉菜单浮于结果区上方，不改变左栏或卡片布局。
- Market Publication 卡片使用高密度横向摘要，样式以用户在“荒野遭遇集”上调整的版本为准，再同步到其他卡片。卡片封面来自 Resource Package Asset；作者可在发布展示信息中选择或上传。所有封面宿主固定为 `63:88` 比例，源图比例不同也使用裁切填充，不拉伸、不随内容改变比例。

## 单向同步

- 同步方向固定为：正式 `.op` → `scripts/` 中的生成器 → `*.generated.ts` / 映射报告 → React/CSS。
- 生成文件不得手改。设计调整先改 `.op`，再运行生成与验证。
- React 可包含事件处理、可访问性和数据绑定等 `.op` 无法表达的实现逻辑；视觉常量与结构差异必须能追溯到 `.op` 或显式例外。
- localhost、PNG、PDF 和 HTML 只作验收结果，不作为设计输入。

## 验证

- 修改正式 `.op` 后必须运行对应生成器，并确认生成文件无陈旧差异。
- 生成器必须在语义节点缺失、名称重复、尺寸或结构不满足约定时失败，不得静默使用默认值。
- 视觉验收同时检查 OpenPencil 截图与真实 App；发现差异时修正映射或回到 `.op` 决策，禁止直接在两端分别调值。
