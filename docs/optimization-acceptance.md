## 渲染与真实浏览器

Node v22.16.0 / win32 x64。敌人 1.0.0 SSR：1 次预热、60 个样本，单 Surface P95 5.912 ms。初始 JS 1,404,923 字节，gzip 408,923 字节。SSR 数值不是浏览器交互耗时，也没有宣称测得浏览器堆内存。

生产构建在本机 4173 预览，使用已安装 Browser 插件验收：

- 冷启动 Player 未加载任何专用模板模块。Creator 导入 1,000 项敌人资源，交替引用 1.0.0/1.0.1；当前卡可显示、编辑，进入 GM 后保留。
- 首张历史卡只增加所需 renderer/editor/core，第二版本增加对应模块。发现并修复最老 renderer 通过 Core 总入口加载全部历史版本的问题；构建门禁额外检查每个 renderer 的 Core 闭包，拒绝跨模板族依赖。某些新版保留同族旧 Core 是既有行为复用。
- 临时移走当前 renderer 构建文件复现加载失败，恢复文件后点击“重试”无需刷新即可恢复卡面。原生模块失败缓存曾使旧重试无效；现在对同源、同构建目录的失败 JS 使用重试地址。验收环境为当前 Chromium；未声称 Firefox/Safari 故障恢复已实测。
- Market 打开真实的 51 项“四圣兽装备”资源包，护甲卡面正常，仅增加当前护甲的专用模块，没有新增编辑器。
- 1,000 项目录展开为 1,001 个 treeitem，但只挂载 1 张规范卡面；过滤后 10 个 treeitem，仍为 1 张。目录文本行未虚拟化，不能宣称总 DOM 恒定。
- 本机 5173 实际 GM 桌面完成放卡与生命/压力操作；保存计数、同步竞争、失败重试由真实 Hook/Repository 测试覆盖。

公共 React、校验器、Markdown 与字体仍为共享成本。保留历史 CSS/实现；没有宣称跨浏览器字体栅格化逐像素一致。

## 发布摘要测量

运行 `node scripts/python.mjs scripts/measure-resource-digest.py`。Python 3.10.8 / Windows x64；每组 5 次，时间取中位数。比较等价旧 framing+join 与当前流式 SHA-256，并逐组断言摘要相同。输入媒体已预分配，tracemalloc 仅测摘要计算新增分配，不是进程 RSS，也不包含图片解码或整个发布请求。

| 输入规模 | 旧时间 ms | 流式时间 ms | 旧新增峰值 bytes | 流式新增峰值 bytes |
| --- | ---: | ---: | ---: | ---: |
| 1 × 1 MiB | 1.151 | 0.579 | 2,101,785 | 5,550 |
| 8 × 1 MiB | 8.112 | 4.067 | 16,786,329 | 7,507 |
| 32 × 1 MiB | 33.011 | 16.086 | 67,133,417 | 15,548 |

这项流式内存改善属于 Python Backend；TS 摘要仍使用既有实现，跨语言输出通过共同 fixtures 验证。
