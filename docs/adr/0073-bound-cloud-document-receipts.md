# 限制云文档幂等回执增长

Status: accepted

对应优化 #65。不修改数据库 schema、文档 payload、媒体或 revision 的所有权。

新写入的回执只保存响应元数据和 payload/assetIds 的 SHA-256，不保存正文或媒体 ID 列表。每个账号的每份文档最多保留 256 份新格式回执，有效期 30 天；写入成功时在同一事务淘汰超期或超量的新格式记录。闲置文档不会主动触发清理，但数量仍有上限。空间为当前文档正文加至多 256 份固定规模回执，不随正文大小乘以保存次数增长。

有效期内的 PUT 重试使用请求正文和资产列表核对摘要，并重建原 revision 的响应；同一 mutation ID 携带不同内容会被拒绝。删除/恢复重试在仍是该操作结果的 revision 时返回相同结果；后续已有操作时报告 revision 冲突，不重新执行旧生命周期动作。

超期或数量淘汰后不承诺返回旧响应，请求重新接受普通 revision 检查。已有文档的旧 revision 请求会冲突；不存在的文档仍遵守首次创建规则。回执不是永久的文档 ID 墓碑。

显式以本地覆盖云端时，客户端先读当前云 revision，再以此作为条件提交本地快照。服务端始终检查 revision，包括 force 请求；读取后有新的云写入则要求用户重新处理冲突。旧客户端携带过时 revision 的 force 请求会收到既有 409 诊断，不能因为回执过期而重新覆盖新编辑。

旧格式完整回执继续读取；新代码不自动迁移或清理既有历史数据。维护工具先只读报告，备份及实际转换/淘汰需要用户单独批准。备份恢复必须与对应应用版本一起进行。

验证覆盖重复 PUT、后续编辑后的旧请求、改动请求内容、数量上限、时间超期、force 重试、删除与恢复重试及当前文档保持。共享协调器继续覆盖三种文档在上传期间的新编辑。
