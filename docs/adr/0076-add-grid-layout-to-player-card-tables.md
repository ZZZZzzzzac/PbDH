# Player 卡牌桌面的格子布局

Status: accepted

Card Table 可声明 `网格布局`，由通用 Player Module 执行矩形占位、拖放、直角旋转和碰撞检查。系统包声明尺寸字段、手上状态、容器状态、容量上限及行列数来源；运行时不识别寻望之心名称或物资规则。

新增的版本化布局片段以 `contracts/system-package/1.0.0/grid-layout.schema.json` 为权威，片段自身显式声明 `版本: 1.0.0`。AJV 与 Python JSON Schema 消费同一组 conformance fixtures。它扩展 modules.json 的可选作者声明，不修改既有 system.json 根 Schema 或已发布摘要。

Resource Picker 通过既有创建卡牌链路领取物资，每次领取建立独立实例，并立即固定资源副本。实例沿用 Character Save 的 Card Table 状态及几何信封：状态为手上或容器状态，rotation 为直角；x/y 是相对于布局最大行列数的百分比，调整容器尺寸不会改变原格子坐标。失败的移动或旋转不会部分写入。

手上是没有格子占位限制的暂存区域，但其物资仍随角色存档持久化。无尺寸的大件物资只能留在手上。缩小容器后越界的物资以待重新安置的手上物资呈现，不清除副本。不同容器不共享占位。旧版手填数据保留在旧记录区，不猜测转换为资源实例。

寻望物资使用独立的 `寻望物资@1.0.0` 模板；不扩展 daggerheart 武器或物品模板，不污染求生者风格的资源入口。

寻望之心现只声明一个主背包，使用3×5、5×5、7×5三个尺寸预设。历史额外容器的实例仍保存在信封中，因其容器不再声明，显示在手上等待重新安置；旧行列字段保留以避免存档丢失。手上使用紧凑标签，拖动浮层以目标格子尺寸显示真实占位。

背包网格始终使用最大行列数计算固定格长，尺寸预设只禁用下方格子。拖动反馈采用目标位置的完整矩形占位，不使用跟随鼠标的浮层。系统包可声明大件记录 longText；无可装包尺寸的资源选择直接追加到该字段，不创建手上实例。旧版手填字段只为旧存档保留，不再显示旧记录区。
