# Make Resource Package Files Self-contained

Status: accepted

A Resource Package logical document is pure structured data containing Asset ID references. When explicitly exported or imported as a file, its Portable Archive is a self-contained snapshot carrying that document and the normalized WebP bytes for every referenced Asset ID, with each unique blob included at most once. A valid archive cannot require a remote image URL, Market availability, or the original Creator account in order to render after installation.

The formal directory Profile and ZIP Profile are logically isomorphic. Normalized relative resource paths are discovered recursively. The root package metadata contains an `emptyDirectories` set only for directories with no descendant files; non-empty directories are inferred and the root does not duplicate a complete file tree. ZIP export creates explicit directory entries for this set, while directory/ZIP import reconstructs it. Paths and `emptyDirectories` are package content and must round-trip; ZIP entry order, compression, timestamps, and Creator list sorting are not. Creator offers deterministic views such as filename or time sorting rather than persisting a manual drag order. A directory extracted from a valid archive can therefore be repacked to the same logical Snapshot Digest even when mechanical ZIP bytes differ.

Portable paths use `/`, remain relative, and retain their valid display spelling, but collision keys use Unicode NFC plus case-insensitive comparison so packages cannot contain names that collide on Windows, macOS, or Linux. Absolute paths, `.`, `..`, empty segments, control characters, Windows reserved names, and segments ending in a space or dot are invalid. A file and directory cannot occupy the same normalized collision key. Collisions reject the complete candidate; import never renames entries silently.

Directory Profiles accept only regular files and regular directories. Symbolic links, hard links, Windows junctions/reparse points, device files, sockets, and other special entries are invalid; the loader never follows them or copies their targets implicitly. ZIP entries marked as links are rejected under the same rule. A user who needs the target content must explicitly copy it into the package as an ordinary file before validation.

Self-contained file transport does not change runtime, App-to-App, or cloud representation. Game Resources still reference Asset IDs rather than embedding bytes. Online APIs transfer logical documents separately from media; Market Backend and local clients store immutable blobs in content-addressed stores and deduplicate them by Asset ID. Exporting bytes into a Portable Archive is not another cloud upload or another physical Backend copy.

The Portable Archive root carries a claimed Resource Package Snapshot Digest for offline integrity checking and display. That field is excluded from its own input. Import recomputes the Digest under the exact Contract and rejects a mismatch before commit; Market installation follows the same completeness boundary, and Market trusts only its server-computed value. A matching Digest does not authenticate the author because a modifier can change content and recompute it; the first release does not add package signatures. A failed or incomplete transfer leaves the previous installed snapshot intact.

The versioned Resource Package Profile defines portable interoperability ceilings such as path length, entry count, per-resource JSON size, media dimensions/pixels, expanded bytes, and compression ratio. Every consumer declaring support for that Contract version must handle packages within those ceilings and reject packages above them as invalid. The concrete ceilings are not chosen by intuition: before Resource Package Contract `1.0.0` can be published, they must be measured against the official migration corpus, representative legacy-format conversions, and dedicated stress fixtures, assigned explicit safety margins, then frozen in the Profile and its boundary fixtures. Development may proceed before that evidence exists, but the Contract remains a prerelease. Account quota, Market upload size/frequency, cloud plans, concurrency, timeout, and traffic controls are separate adjustable product or deployment policies. A Contract-valid local package may therefore be refused for Market publication by a policy diagnostic without being relabeled as Contract-invalid.

## Consequences

- Installed Resource Packages remain usable offline after Creator deletion, publication withdrawal, Market outage, or remote cache loss.
- Third-party remote image URLs must be fetched, normalized, and admitted as media candidates before a PbDH Resource Package can be created. Failure is explicit conversion loss, not a hidden online dependency.
- Local storage deduplicates the same normalized image across resources and packages even though each separately exported archive must carry the bytes needed for its own portability.
- Archive path traversal, Unicode/case collisions, duplicate normalized paths, reserved or illegal segments, links and special files, entry count, compressed and expanded byte limits, media dimensions, media hashes, and atomic import require contract fixtures and security tests.
- Contract fixtures lock the versioned interoperability ceilings. Market and account policy tests use distinct diagnostic codes and may impose stricter publication/service limits without changing local file validity.
- Resource Package Contract `1.0.0` cannot be published until the measured corpus, chosen safety margins, exact ceilings, and pass/fail boundary fixtures are reviewed together; later ceiling changes require a new Contract version.
- File/directory normalized-path collisions are errors. `emptyDirectories` entries are normalized, unique, have no descendant files, and participate in the logical Snapshot Digest; redundant non-empty directory entries are invalid rather than a second file-tree authority.
- Lazy Market browsing may use remote thumbnails, but an installation cannot be declared complete until its required package snapshot and media are locally available.
